# dotfiles: Arch + mangowm on a ThinkPad T14

An Arch Linux desktop on [mangowm](https://github.com/mangowm/mango) (a wlroots compositor), themed
from one switchable palette (default: VS Code's **Dark 2026**). Every app has its own folder in this
repo; GNU stow links each folder's `.config/`, `.local/` and dotfiles into your home.

- [Install](install.md): a fresh Arch install becomes this desktop with one command
- [Layout](#layout): how an app folder is built, and how to add one
- [Session](session.md): how the session starts, idles, locks and logs out
- [Theming](theming.md): palettes, roles, templates, `theme set`
- [Keybindings](keybindings.md)
- [Testing and CI](testing.md): `tests/run`, the clean-install VM on runner-up
- [Installed versions](reference/installed.md) on the reference machine

## Layout

```
~/dotfiles/
  bootstrap.sh      fresh Arch install -> this desktop (clone + install.sh)
  install.sh        packages → theme → link → system → setup → units (idempotent), --check
  .stowrc           stow defaults (--target=~ --no-folding) for running stow by hand
  <app>/            one folder per program; every part is optional, every app uses the same ones:
    packages         pacman/AUR packages (one per line, # comments)
    pkg/<name>/PKGBUILD  a program that isn't packaged anywhere, built with makepkg
    .config/… .local/… .zshrc …   dot-entries: linked into $HOME (stow, one link per file)
    root/…           system files: copied to / (install.sh --system)
    *.tmpl           templates (palette colors, {{user}}, {{home}}), rendered in place, anywhere
    render.sh        palette art that isn't a template (the greeter wallpaper)
    reload.sh        recolors the running app after `theme set`
    setup.sh         state that isn't a file: services, gsettings, login shell
    .config/systemd/user/*.service   user units, enabled by install.sh
    .stow-local-ignore  marks the app as linked; keeps everything but dot-entries out of $HOME
    .gitignore       rendered and generated files
  theme/            the renderer (~/.local/bin/theme) and palettes/
  tools/            docs (generator/checker), setup-lib.sh, test-home
  tests/            tests/run + tests/unit.d/*-test.sh
  docs/             you are here
```

Links are one per file, so apps can keep their own data next to them (qutebrowser's bookmarks,
opencode's password file) without it landing in the repo. A **new file** in an app folder goes live
after `./install.sh --link`; editing an existing file is live at once. The repo owns every file it
links: if an app replaces a link with a real file, `install.sh --check` reports it and the next
`install.sh` backs the file up and restores the link.

### Adding or changing an app

1. `mkdir <app>` with the parts it needs from the list above (nothing else: no special cases);
   copy `.stow-local-ignore` from another app if it links into your home.
2. Colors only through the palette: `*.tmpl` files using `{{role}}` (see [Theming](theming.md));
   list the rendered names in `<app>/.gitignore`. `theme lint` fails on a color literal.
3. `./install.sh --only <app>` (or the phases you need).
4. `tools/docs` stubs `docs/apps/<app>.md`: describe the app there; the reference part is generated.
5. `tests/run` and `tools/docs --check` must pass. Commit the app, its docs and
   `docs/reference/installed.md` (`tools/docs --snapshot`) together.
