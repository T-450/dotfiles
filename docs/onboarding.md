# Get started

In this tutorial, you install this desktop on a fresh Arch Linux machine, check that it matches
the repo, change its colors, and add a program the same way every program in this repo is added.
It takes about 30 minutes, most of it package downloads.

You need a fresh Arch Linux install with a working network, and a user in the `wheel` group.
archinstall's minimal profile is enough.

## Install the desktop

1. Log in as your user, not root, and run:

	```bash
	curl -fsSL https://raw.githubusercontent.com/T-450/dotfiles/main/bootstrap.sh | bash
	```

2. Answer the prompts as they come:
	- The `[sudo] password` prompt asks for your password, because install steps need root.
	- The GitHub sign-in (`gh auth login`) is for runner-up, the CI coordinator. If you skip
	  it, the desktop still works and runner-up stays off.
	- `Your name, for git commits` and `Your email, for git commits` appear only when your git
	  config has no identity. They fill `~/.config/git/config`.

	The run ends with the `==> units` step.

3. Reboot. The login screen is sysc-greet with the "Mango" theme. Log in to start mango, with
   waybar at the bottom.

## Check that it matches the repo

Every later change uses these two checks, so run them once now.

1. In a terminal (alt+return), run:

	```bash
	cd ~/dotfiles && ./install.sh --check
	```

	You see:

	```
	ok: home and system files match the repo
	```

2. Run the tests:

	```bash
	tests/run
	```

	The last line is:

	```
	all 8 files passed
	```

## Change the colors

1. List the palettes. The `*` marks the active one:

	```bash
	theme list
	```

	```
	  catppuccin-mocha
	* dark-2026
	  light-2026
	  tokyo-night
	```

2. Switch to Tokyo Night:

	```bash
	theme set tokyo-night
	```

	You see `tokyo-night: rendered 22 files`. Window borders, waybar, notifications, and the
	wallpaper change at once. Open a new terminal to see its new colors.

3. The login screen lives outside your home, so it changes only when you run
   `./install.sh --system`, which asks for sudo. `theme set` reminds you.

4. Switch back with `theme set dark-2026`, or pick a palette with super+shift+t.

## Add a program

Every program is a folder in `~/dotfiles`. Here you add btop, a system monitor.

1. Create the folder and declare the package:

	```bash
	cd ~/dotfiles
	mkdir -p btop/.config/btop
	echo btop > btop/packages
	```

2. Add its config. `.config/btop/` inside the folder mirrors `~/.config/btop/`:

	```bash
	printf 'color_theme = "TTY"\nupdate_ms = 1000\n' > btop/.config/btop/btop.conf
	```

	The `TTY` theme uses the terminal's colors, so btop follows the palette. Never write a color
	value in a config. `theme lint` fails on one.

3. Mark the folder as linked into your home:

	```bash
	cp foot/.stow-local-ignore btop/
	```

4. Install it. The command upgrades the system, installs btop, and links the config:

	```bash
	./install.sh --only btop
	```

	Among the output you see:

	```
	==> link
	stowed  1 apps into /home/<you>
	```

5. Check the link:

	```bash
	ls -l ~/.config/btop/btop.conf
	```

	The file is a link into the repo, `../../dotfiles/btop/.config/btop/btop.conf`. Edit the file
	in the repo, and btop reads the change at its next start.

6. Document the program:

	```bash
	tools/docs
	```

	```
	stub    docs/apps/btop.md
	update  docs/README.md
	update  docs/apps/btop.md
	```

	Open `docs/apps/btop.md` and replace `(what it is, one sentence.)` with a sentence about
	btop. Leave the part between the `generated by tools/docs` markers alone. `tools/docs` keeps it
	current.

7. Run the checks:

	```bash
	theme lint && tools/docs --check && tests/run
	```

	All three pass.

8. Commit on a branch and push:

	```bash
	git switch -c btop
	git add btop docs
	git commit -m "btop: system monitor in the terminal's colors"
	git push -u origin btop
	```

	The push starts CI. It installs everything on a fresh Arch virtual machine, runs `install.sh`
	a second time to check that nothing changes, and runs the tests. Watch it with
	`gh run watch`.

9. When CI passes, merge:

	```bash
	git switch main && git merge --ff-only btop && git push
	```

You added a program the way every program here is added: a folder, its packages, its files, its
page in `docs/`.
