# greeter

The login screen: greetd running stock sysc-greet in the small mango session that `sysc-greet-mango` ships. Its theme, ASCII art, background, last user and session are sysc-greet's own; it remembers the last user and session itself. The repo owns only the greetd config (`greeter/root/etc/greetd/config.toml`, copied to `/` by `install.sh --system`, runs the greeter through `systemd-cat -t greeter`) and enabling greetd.

sysc-greet runs inside kitty: `sysc-greet-mango` depends on it, starts the login UI in it (`/etc/greetd/mango-greeter-session.sh`) and starts more kittys itself for a second monitor. So kitty stays installed, but only for the login screen; the desktop's terminal is [Ghostty](ghostty.md). `.local/share/applications/kitty.desktop` and `kitty-open.desktop` mask kitty's own entries, so it is not in the launcher and opens no files or links (kitty-open was the handler for `.sh` files and `ssh://` links): `Hidden=true` for GLib (Thunar, Firefox, rofi), `Exec=false` for `xdg-open`, which ignores `Hidden`.

If the login screen doesn't come up, you get a text login instead. greetd then logs only "greeter
exited without creating a session" (`journalctl -b -u greetd`), and after five tries in a row it
stops trying until the next boot. The greeter's own output, mango, kitty and sysc-greet included,
is in `journalctl -b -t greeter`. Once the cause is fixed, `sudo systemctl restart greetd` brings
the login screen back without a reboot.
