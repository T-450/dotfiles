# swayosd

On-screen display for volume and brightness, and the commands the keys run. It is a Material 3 slider pill ([SPEC-bar](../designs/material-shapeshifter/SPEC-bar.md)): `surface_container_high`, corner full, the icon in `on_surface_variant`, a 16px track in `surface_container_highest` with the level in `primary`. swayosd centres it horizontally; `swayosd.service` passes `--top-margin 0.0625` (a fraction of the room above and below it), which puts it at the top, 8px under the bar.

`osd-volume up|down|mute|micmute` and `osd-brightness up|down` (keys, with the OSD) or `bup|bdown` (bar scroll, plain brightnessctl at 1% steps).

Brightness needs write access to `/sys/class/backlight/*/brightness` (root:video, group-writable): swayosd and waybar run as systemd user units, outside the logind session, so brightnessctl's fallback (logind's `SetBrightness`, which only answers processes inside the session) refuses them and the keys and the bar scroll do nothing. `setup.sh` adds you to the `video` group; it applies from the next login.

**User units** (enabled by `install.sh --units`): `swayosd.service`

**`setup.sh`** (run by `install.sh --setup`): your user in the video group, so the brightness keys (swayosd) and the bar's brightness scroll (waybar) can write the backlight. Both run as systemd user units, outside the logind session, so logind's SetBrightness (brightnessctl's fallback without write access) refuses them; the backlight's brightness file is root:video and group-writable. Applies from the next login.

**`reload.sh`** (run by `theme set`): restart swayosd.service, which reads its colors at startup. try-restart leaves a stopped unit alone (a bar hidden with its toggle stays hidden).
