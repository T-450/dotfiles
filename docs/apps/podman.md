# podman

Containers without a root daemon: rootless Podman behind the `docker` command (podman-docker), `docker compose` through podman-compose, and a Docker-compatible API socket for testcontainers and devcontainers.

There is no Docker Engine. `docker run`, `docker ps`, `docker build` and `docker compose up` run Podman as you, not as root: no `docker` group (which would be root-equivalent), and published ports are bound by a user process, so ufw filters them like any other port ([base](base.md)). Publish to `127.0.0.1` (`-p 127.0.0.1:5432:5432`) unless another machine needs the port. `/etc/containers/nodocker` silences the "Emulate Docker CLI" note the docker command would print, including in every new shell (zsh's docker plugin calls `docker --version`).

- **Short names**: `docker run postgres` searches Docker Hub (`registries.conf.d/50-docker-hub.conf`), as docker does. Arch sets no search registry and aliases only some names (alpine, node).
- **Compose**: `docker compose` and `podman compose` hand off to podman-compose, pinned by absolute path in `containers.conf.d/50-compose.conf` with its per-call banner off. Without the pin, podman would prefer a `docker-compose` found on `PATH` or in Docker's CLI plugin directories, which a GUI's onboarding could add silently. A compose file that uses a Compose feature podman-compose lacks fails here; then add `docker-compose` and change the pin, never both.
- **The API socket**: `podman.socket` (enabled for every user by `setup.sh`, so it also works in CI before any session) listens at `$XDG_RUNTIME_DIR/podman/podman.sock`; a connection starts podman. `DOCKER_HOST` points clients there. It is set in `zsh/.zshrc`, not mango's `env.conf`: every client (testcontainers, SDKs, the devcontainer CLI) starts from a shell, and zsh expands the per-user runtime dir. An explicit `DOCKER_HOST` wins.
- **Devcontainers**: the devcontainer CLI comes from mise (`npm:@devcontainers/cli`): `devcontainer up --workspace-folder .`, then `devcontainer exec --workspace-folder . bash`. It drives podman through the docker command; compose-based devcontainers go through podman-compose.
- **Subordinate IDs**: rootless containers map their users onto your `/etc/subuid` and `/etc/subgid` range. `setup.sh` adds a free 65536-ID range only if useradd didn't. Files a container writes into a bind mount belong to that range (an image that runs as user 999 writes as 100998); `podman unshare chown` or `--userns=keep-id` gives them back.

Troubleshooting: "Cannot connect to the Docker daemon at unix://.../podman.sock" means the socket is off: `systemctl --user status podman.socket`, or start it with `systemctl --user start podman.socket`. A shell started before this change lacks `DOCKER_HOST` until a new one opens.

Rollback: `podman system reset` (deletes every container, image and volume), `sudo systemctl --global disable podman.socket`, revert the commit, `sudo pacman -Rns podman-compose podman-docker podman`, and remove the three files under `/etc/containers` named below.
