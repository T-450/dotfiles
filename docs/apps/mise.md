# mise

Language toolchains, build systems and editor tooling, pinned by a committed lockfile.

[`config.toml`](../../mise/.config/mise/config.toml) names each tool and the version channel it follows (`go = "1.27"`, `node = "26"`). `mise.lock` next to it pins the exact version of each, plus the URL and SHA-256 of every download. `locks/` holds the dependency lockfiles of the npm tools. mise writes both, so never edit them by hand. `setup.sh` runs `mise install --locked` from `/` when the lockfile pins a tool that isn't installed, then prunes versions nothing uses. Running from `/` keeps a `mise.toml` or `.nvmrc` in your home or working directory out of the install.

## Where a tool comes from

mise installs every tool except these, which come from pacman:

- `clang`, `lldb` and `mold` (`clang/packages`): they build and link against this system's glibc and headers. `gcc` and `make` come with `base-devel`.
- `meson` (`clang/packages`): it runs on the system Python, and Arch rebuilds it when that Python moves.
- `jdtls` and its Java runtime (`helix/packages`): no mise backend ships the Java language server.

There is no global mise Python. `python3` stays `/usr/bin/python3`, which runs `theme` and `tools/docs`. uv installs a Python per project.

The `asdf` and `vfox` backends are off because they run third-party plugin shell code. mise checks provenance (cosign, SLSA, GitHub attestations) when it locks a version, and the lockfile's SHA-256 when it installs one. A release must be 24 hours old before mise picks it.

## Update the toolchain

```bash
mise use -g TOOL@CHANNEL   # add a tool
mise upgrade --global      # move every tool to the newest version in its channel
mise -C / lock -g          # after you change a channel in config.toml
git diff mise/             # review, then commit mise/.config/mise/
```

All three write through the links into the repo: `config.toml`, `mise.lock` and `locks/`. Commit `mise/.config/mise/`. On every other machine, the next `install.sh` installs the new versions and prunes the old ones.

## Use another version in a project

In a project, `mise use node@24` writes a `mise.toml` there. mise asks before it loads a project config it hasn't seen. Run `mise trust` to accept it, then `mise install`. mise also reads `.nvmrc`, `.node-version` and `rust-toolchain.toml`, so a project that pins its version in one of those gets that version inside its directory.
